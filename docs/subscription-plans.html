Plans & API Entitlements — as built · v2

Aligned to QueueRx Pricing Reference v2 (Basic / Advanced / Ultimate). How the backend actually enforces entitlements.

  • Entitlement is per pharmacy (medical_store), not per user.
  • Guard: a gated route calls ensure_feature(db, medical_store_id, Feature.X) after the ownership check → reads the store's active subscription → the plan's features list (DB JSON) → HTTP 402 if missing/expired or the plan lacks the flag.
  • Flag keys follow the v2 developer contract (snake_case); the Feature enum holds all 20 boolean flags.
  • Expiry is lazy, no grace period. Plans are additive.

Not feature-gated (open to any authenticated user)

  • Auth & account: /user/*
  • Pharmacy CRUD: /pharmacy/* (multi-location is structural)
  • Activity feed: GET /pharmacy/{ph_id}/activity
  • Document status: GET /documents/{doc_key}, GET /documents/
  • Subscription self-service: GET /plans, GET /subscription/{store}, POST /subscription/subscribe, PUT /subscription/upgrade (owner or admin)
  • Admin: /admin/subscriptions*, /admin/plans* (ADMIN-only)

Known gaps & open items

Critical  Self-serve subscribe/upgrade grant plans for free. No payment step — an owner can POST /subscription/subscribe for ULTIMATE at $0. Treat as admin-only until billing lands.

Medium  Ultimate-only validation checks aren't separately gated. ndc_claim_mismatch_checks, days_supply_validation, discontinued_drug_detection run inside the shared validation engine reached by the Advanced-gated /dispenses + /dispenses/validate, so Advanced stores get them too. Needs a plan-aware validator.

Medium  No ADMIN bypass in ensure_feature — admins get 402 on unsubscribed stores (fails closed).

Low  Existing pharmacies need backfill — hard-deny 402 until assigned a plan.

Low  No payment gateway — subscribe/upgrade/revoke are state-only, monthly only.

Closed in this pass

✔  Cross-store list endpoints gated: GET /invoices/ (→ invoice_to_inventory_auto) and GET /reports/ (→ top_quantity_drug_report) now hide rows for non-entitled stores via feature_gate.entitled_store_ids. GET /documents/* stays status-only metadata.

✔  drug_reconciliation_limit enforced at POST /dispenses — a report exceeding the plan cap (250 on Basic/Advanced) is rejected with 402.

Admin & lifecycle controls

  • Assign / override: POST /admin/subscriptions
  • Modify: PUT /admin/subscriptions/{id} (plan / status / expiry)
  • Revoke: POST /admin/subscriptions/{id}/revoke
  • Catalog: POST/PUT /admin/plans — re-scope any tier's features without a redeploy.
  • Audit: every change appends a SubscriptionEvent (SUBSCRIBE / UPGRADE / DOWNGRADE / REVOKE / ADMIN_MODIFY).
